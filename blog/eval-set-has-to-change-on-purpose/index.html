旧题全绿不等于能挡合并

全绿只能说明旧题没退步。我差一点把它读成循环有用。

新题得故意加，而且得指到一次事件。没有事件的印象，先放在未准入，可以跑，不挡事。等有了事件再谈能不能挡合并。

修完的失败案例不能从集合里消失。消失了，再犯的时候会像个新问题。失败版本和通过版本用同一个题号的两个文件，都留着。

旧题为了保持全绿去改判定，不行。改判定就另存，日期写在文件头上。

冻结的时候我想加题，手会痒。未准入那个目录就是给这个痒的。

未准入的题放在集合外面的文件夹。名字里带日期。哪天它有了事件编号，再考虑搬进去。搬的时候单独一个提交。

未准入的题单独一个文件夹，名字里带日期。哪天有了事件编号再搬，搬的时候单独提交。

搬进集合的提交里只有题，没有顺便改断言。顺便改的话，我就分不清是题变了还是判定变了。

单独提交里我看过 diff，只有题文件，没有断言文件。
