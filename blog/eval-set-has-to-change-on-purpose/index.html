自迭代最容易假装成功的地方，是评测集没有变

二月我检查自己那份很短的阻塞题集。它很稳定。稳定让我安心，也让我迟钝。线上若出现一种新的失败，旧题集仍然全绿。全绿会被我误读成循环有效。

题集要变，但只能故意变。从真实事件里抽出一种新的失败，写成能判定对错的题，放进观察或阻塞。没有事件，就不要凭印象加题。印象题会把题集重新变成心情。

旧题不能为了保持全绿而改判定。改判定要留版本。新题失败，先当它是题或系统的问题，不立刻从集合里删掉以求好看。

假装成功的另一种是只把已经通过的案例放进回归。失败过的案例如果修完就消失，集合就只记得胜利。胜利集合不能发现复发。

我没有统计复发率。没有足够的样本时，比率没有意义。有意义的是：这个失败还在不在集合里。在，就还能被看见。

二月的规则：新增题必须指向一次事件；删除题必须写下为什么它不再代表那类失败。两句理由都没有，集合就冻结。

冻结不是懒。冻结是为了防止我在绿灯的诱惑下改题。

自迭代如果只优化模型对旧题的措辞，那是在打磨答案，不是在接住生产。

冻结期间我想加题，就把题写在冻结文件外面，标题标明未准入。未准入可以跑，不能影响阻塞。等它有了事件指针，再讨论准入。

胜利案例保留失败版本。失败版本是复发时的对照。只留最后一次通过，对照就没了。没了对照，复发会被当成新问题。

失败版本和通过版本用同一个题号的两个文件。文件都在，复发时不用回忆。回忆会把旧失败说得比当时轻。当时的文件不会变轻。

我又把当天的输入和输出各存了一份，不把结论写进文件名。文件名只写日期。结论写在正文里。正文可以错，文件还在，就能对照。对照时先看自己有没有把未知说成完成。说成完成的那一句划掉，但不删文件。划掉是为了以后看见自己当时多想结束这件事。输入输出都保留，避免只留下好看的那一稿。
