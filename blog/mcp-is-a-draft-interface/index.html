超时和空结果还得自己定

发现和调用分开，比把函数说明全写进一个提示清楚。这点我认。

超时、空结果之后能不能发挥，还是我自己补的。协议把这些留成各自实现的话，它就是草案。草案可以试，生产路径上刚写好的失败处理先不动。

语音和文本的时钟不一样。登记在一起可以，共用一个超时会把实时那条拖坏。

只读工具失败时，给出去的句子只有“这次没取到”。不写长原因。长原因常常是失败之后它开始发挥。

本地那个工具的描述只有两句：返回标题，不返回正文。我把示例里的长介绍删了再注册。长介绍会让调用变宽。

工具描述我只留两句：返回标题，不返回正文。示例里的长介绍删了再注册。

长介绍删掉再注册。留下的两句很干，调用也没那么爱往后说。

注册前我把描述贴回终端看一遍。看着太长就再删。

本地工具的超时我写成 2 秒。空结果和超时在日志里是两个词。
