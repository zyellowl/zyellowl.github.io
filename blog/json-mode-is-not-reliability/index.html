JSON 模式用了几周，留下的坏样本都是括号完整、内容另补的

括号完整的时候，我第一反应是下游逻辑有问题，不是它在编。排查方向被格式带歪了。

要是“可靠”指程序别因为解析崩掉，JSON 模式有用。要是指内容能当记录，它基本没管。我以前把这两件写成一个词。

重试也清楚了一点：形状明确，失败可以再要一次。我的调用还没有副作用，所以重试没事。一旦会写入，再试就是另一件事，注释里先写上，免得以后照抄。

解析函数旁边我留了句：这里保证能读。调用方必须处理作废，测试不去断言它的措辞，措辞一换版本就碎。

作废和成功分成两个返回值。调用的地方不处理作废，测试就不会过。这个痛放在写代码的时候，不放在线上用户看见乱七八糟的 JSON 的时候。

测试不断言措辞。措辞一换版本就碎，还会让我去迎合句子。

措辞断言我删过一批，剩下的只查编号和空结果。

那周的坏样本我留了三份，都是括号完整、内容是补的。
