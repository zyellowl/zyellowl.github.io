GPT-5 发布当周，我没有换掉评测集

八月上旬 GPT-5 公开。当周我做的唯一一件比较，是把旧题集跑一遍。没有为它设计新题，没有把思考长度写进通过条件。

有的题通过得更干脆，有的题失败得更会解释。解释不改变失败。空结果时的建议仍然算失败。这条从 2023 年放到现在，发布周最容易破。

我把输出按模型版本存档，判定版本不动。三月 2024 年对 Claude 3 做过同样的事。重复是故意的。每次发布都想改题集的冲动，要用同一种动作挡回去。

编码仓库里我没有当天切换默认模型。默认要等我看完文件列表和失败种类，而不是等热度。热度不是验收。

速度和价格的变化我注意到了，但不写进这篇当结论。一个星期的感觉，去年已经证明会骗人。感觉只够决定要不要继续观察。

观察继续用事件日志。没有事件的通过，不算通过。六月写过。发布周再强调一次，因为演示最喜欢没有事件的成功。

旧题集很短。短意味着很多能力我没测。没测就别说。说“全面变强”是把没测的部分送人。

八月底的决定：默认模型名单不变，直到某一题的失败形状我能解释为什么变了。解释不了，就还在看。

当周的输出我按题号对比旧输出，只标验收是否变化。措辞变化不记录。记录措辞会让我陷入谁更好听。好听不是这个星期的工作。

默认名单冻结写在配置的注释里，注释包含解冻条件：某一题的失败形状能被事件解释。没有事件的变好，不构成解冻。

解冻条件写进配置之后，我在发布周打开过一次配置，确认自己没有临时改默认。打开本身是仪式，但是有用的仪式。没有这个动作，手会先于判断。

我又把当天的输入和输出各存了一份，不把结论写进文件名。文件名只写日期。结论写在正文里。正文可以错，文件还在，就能对照。对照时先看自己有没有把未知说成完成。说成完成的那一句划掉，但不删文件。划掉是为了以后看见自己当时多想结束这件事。输入输出都保留，避免只留下好看的那一稿。
