测试绿了 README 却写了重试

不是公司仓库。第一周的顺序改成先看文件列表，再看测试。列表里出现任务没提到的路径，先还原，不让它再修。再修一次常常继续扩散。

允许列表一开始只有任务点名的目录。新建的文件不在列表里，测试通过也还原。还原之后不听它解释，解释会说服我把列表放宽。

它还整文件格式化，diff 一下子很大。大 diff 的时候我已经读不完了。后来限制在一个目录。

需要密钥的仓库这周没开。建议里即使出现密钥文件的名字，我也不把那个文件给它看。建议不是授权。

留下的是一张“不该出现的路径”清单，不是成功了几次。

允许列表外的注释我还原了三次。第三次它换了个说法，还是在解释为什么该留着。我没看完那段解释，直接还原。看完就会心软。

那个小仓库是我自己的笔记脚本，语言是 Python，测试就是几个断言。任务我写得很窄：给某个函数补一个空输入的分支。它做到了，测试绿了，同时改了 README 的一行，把函数说成会自动重试。代码里没有重试。

README 的 diff 不长，所以更危险。我几乎滑过去。后来规定说明文件默认不在允许列表里。要改说明，单独开一次任务，只含那个文件。

格式化是另一次。它跑了格式化命令，几十个文件的空白变了。测试当然还是绿的。我把那次提交整段还原，在说明里写上不要顺便格式化。顺便两个字最容易把复查弄丢。

密钥那条是预防。仓库里本来没有密钥。它在注释里建议我把 token 放到某个环境变量，并写出了一个示例文件名。示例文件我没有创建。创建了就会有一天被读进去。

一周结束我没有统计它改对了几次。对的那些我记得，错的路径我写成了清单。清单现在还有三行。三行比一句“挺好用”有用。

补空输入那个函数，原来是直接取字典的键。空字典会抛。我让它加分支，返回一个空结果而不是抛。测试是我先写的，断言空字典得到空列表。它改完测试过了。

README 那一行是后发现的。我用 git diff --stat 看，除了那个 py 文件还有 README.md。打开才看见“会自动重试”。函数里没有 retry。这种句子测试覆盖不到。所以允许列表后来把 md 排除了。

格式化那次我记得很清楚，因为 diff 突然上百行。我用 git checkout 把那次整段退回去，再在任务说明顶部写：不要跑格式化。说明它有时当建议，有时当命令。我现在把这种话写在它会读到的任务文件第一行，并且允许列表里没有格式化脚本。

一周里我合进去的只有那个空输入分支。其他改动都还原了。合进去之前我自己读了那一个函数。读完才提交。这就是我现在还愿意用它的方式。

空字典那个测试是我先写的。函数原来直接取键，空输入会抛 KeyError。我把期望写成返回空列表。它改完，pytest 过了，我才去看 diff。

README 的那行不在测试里。git diff --stat 比测试输出先看，就是因为这次。stat 里多一个 md，我就打开。打开才看见自动重试。

格式化那次的还原命令是 git checkout -- 。还原之后工作区干净，我在任务文件第一行加了不要格式化。第一行它会读到。放在最后它有时读不到。

密钥示例文件我没有创建。创建了就会出现在仓库里，下一次允许列表如果写宽，它就能读到。不创建比写一条禁令省事。
