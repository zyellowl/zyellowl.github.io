提示词不是配置文件

二月我开始认真写提示。方法很工程师：分节、列约束、给例子、规定输出格式。我把它当成一份会生效的配置。同样的输入多跑几次，结构大体还在，细节会漂。有一次它把“只列出观察”理解成“观察加建议”，因为我在上一节举过建议的例子。

配置文件不会因为例子的语气而改行为。提示会。例子比规则更靠近它要模仿的东西。我把例子删短，规则留着，漂移小了一些，任务也变笨了一些。两边我都想要，当时没有办法同时拿到。

我还试过把角色写成“你是一位审慎的摄像师”。句子立刻更像旁白，事实没有更稳。角色词改变的是文体，不是它有没有看过画面。这个月我终于把这两件事拆开：文体可以借提示塑造，事实必须来自我提供的材料。

另一个习惯是把提示越写越长，觉得遗漏就再加一条。加到后面，前面的约束它会忘。我没有测量遗忘的位置，只是反复看到后半段的格式还在、前半段的禁令丢了。长提示不是更完整的合同。

二月的做法变得无聊而有用。提示只写三件事：材料是什么，不要做什么，输出长什么样。材料本身单独放，不和规则搅在一起。仍然会错，但错的时候我知道该改材料还是改规则。

情人节这天我把一份两页的提示删成半页。演示没那么华丽，复查快了。我把它当成这个月的进度。

我给自己加了一条改提示的纪律：每次只改一行，并保存改之前的输出。同一材料连跑三次，三次不一致就先别解释原因，先承认不稳定。不稳定的提示不配继续加规则。加规则是在不稳定上盖房子。

纪律执行了两周，文件从两页回到半页。半页里仍然会错，但错的位置我能指给别人看。能指出来，协作才开始。指不出来的提示，只适合一个人在夜里自我感觉良好。

半页提示定下来之后，我用同一材料在三个晚上各跑一次。三次的差异只允许出现在措辞，不允许出现新物体。出现新物体，就把最近加的那一行删掉，而不是再加一行去堵。堵是去年的做法。
